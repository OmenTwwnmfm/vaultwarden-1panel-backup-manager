# 快速开始

本项目用于保护已经由 1Panel 应用商店安装的 Vaultwarden 实例。1Panel 继续管理应用、Docker、HTTPS 和反向代理；本工具负责数据备份、加密、GitHub 同步、恢复和诊断。

## 适用条件

- Ubuntu / Debian，使用 systemd。
- Docker 已由 1Panel 安装并运行。
- Vaultwarden 已通过 1Panel 应用商店安装。
- 使用 SQLite，容器内 `/data` 挂载到 VPS 主机目录。
- 有一个独立的 GitHub Private 备份仓库。
- 有原 age 公钥；对应私钥离线保存。

本工具不会安装 Docker、Vaultwarden、HTTPS 证书或反向代理。

## 1. 下载项目

```bash
sudo apt update
sudo apt install -y git
sudo git clone https://github.com/OmenTwwnmfm/vaultwarden-1panel-backup-manager.git /opt/vaultwarden-1panel-backup-manager
cd /opt/vaultwarden-1panel-backup-manager
sudo bash ./run.sh
```

源码仓库为 Public，所有人均可直接 HTTPS 克隆，不需要 GitHub 认证；只有数据备份仓库必须为 Private。首次配置必须在 SSH 交互终端运行。

## 2. 首次配置

在管理器中选择 `[01]`。向导将：

1. 扫描 Vaultwarden 容器。
2. 读取容器 `/data` 对应的主机挂载目录。
3. 确认目录中有非空 `db.sqlite3`。
4. 检查备份工具依赖。
5. 配置 GitHub SSH Deploy Key、仓库地址和分支。
6. 配置 age 公钥、备份目录和保留策略。
7. 展示摘要，输入 `yes` 即可保存配置（不区分大小写，`YES`、`Yes` 也可以）。

如已有历史备份，必须使用创建这些备份时的原 age 公钥；不要新生成密钥替代。age 私钥至少离线保存两份，不要提交到 GitHub。

## 3. 首次手动备份

选择 `[02]`，核对容器名称和 `/data` 主机路径，输入 `yes`（不区分大小写）。备份完成后，GitHub Private 仓库中应看到 `.tar.gz.age`、`.manifest.json.age` 和对应 `.sha256` 文件。

## 4. 验证备份

选择 `[08]`，从 GitHub 选择备份并执行 SHA256、age 解密、tar 内容和 SQLite 检查。离线私钥可以临时提供，检查完从 VPS 删除临时私钥副本。

## 5. 启用自动备份

先完成一次手动备份并验证，再选择 `[09]` 安装 systemd timer。默认每天 VPS 本地时间 05:20，也可选择每周或每月计划。它不依赖 1Panel 计划任务。启用后检查 `[10]`。

## 6. 全局命令

每次执行 `sudo bash ./run.sh` 时，启动器都会自动安装或修复 `/usr/local/bin/vbm`。之后在 VPS 任意目录执行 `vbm` 即可进入交互式菜单。

## 7. 重要提示

- 源码仓库与备份仓库分开；备份仓库必须 Private。
- 服务器日常加密只需要 age 公钥，私钥离线保存。
- 备份期间 Vaultwarden 会短暂停止；快照完成后会尽快启动，再上传 GitHub。
- GitHub 删除当前分支文件不会清理 Git 历史对象，需留意仓库体积。
- 首次正式依赖备份前，至少进行一次真实解密验证和隔离恢复演练。

性能监控在主菜单 `[20]`，记录备份和恢复各阶段耗时，支持最近运行统计、指定运行详情与 CSV 导出。性能记录保存在 `/var/lib/vaultwarden-backup/performance.tsv`。v1.4.3 手动备份直接调用项目目录内的计时 worker，并将容器停止、SQLite 检查、tar+age 快照、Docker 启动命令和健康检查等待独立计时；systemd 仍使用系统安装版，源码更新后请先运行菜单 `[07]` 同步后台脚本。所有 `YES` 确认均不区分大小写，输入 `yes`、`YES` 或 `Yes` 均可。

完整说明见 [完整使用手册](完整使用手册.md)。


## 性能记录排查

手动备份完成后，日志应出现 `[性能] 已启用阶段耗时记录` 和多条 `[耗时]`。检查记录文件：

```bash
ls -lh /var/lib/vaultwarden-backup/performance.tsv
tail -n 20 /var/lib/vaultwarden-backup/performance.tsv
```

如果文件不存在，确认使用的是当前最新版本，并从项目目录启动 `vbm`。本版菜单 `[02]` 会调用当前项目目录中的计时版 worker；systemd 自动任务仍调用系统安装版 worker，更新项目后先执行菜单 `[07]` 同步后台脚本。
