# 快速开始

本项目用于保护已经由 1Panel 应用商店安装的 Vaultwarden 实例。1Panel 继续管理应用、Docker、HTTPS 和反向代理；本工具负责数据备份、加密、GitHub/WebDAV 同步、恢复和诊断。

## 适用条件

- Ubuntu / Debian，使用 systemd。
- Docker 已由 1Panel 安装并运行。
- Vaultwarden 已通过 1Panel 应用商店安装。
- 使用 SQLite，容器内 `/data` 挂载到 VPS 主机目录。
- 有独立的 GitHub Private 备份仓库或 WebDAV HTTPS 专用目录。
- 有原 age 公钥；对应私钥离线保存。

本工具不会安装 Docker、Vaultwarden、HTTPS 证书或反向代理。

## 1. 下载项目

```bash
sudo apt update
sudo apt install -y git
sudo git clone https://github.com/OmenTwwnmfm/vaultwarden-1panel-backup-manager.git /opt/vaultwarden-1panel-backup-manager
cd /opt/vaultwarden-1panel-backup-manager
sudo bash ./run.sh
```

源码仓库为 Public，所有人均可直接 HTTPS 克隆，不需要 GitHub 认证；只有数据备份仓库必须为 Private。保持 `/opt/vaultwarden-1panel-backup-manager` 及项目脚本由 root 所有且不可被组或其他用户写入；启动器会拒绝从 `/home/<user>`、`/tmp` 等不安全路径以 root 启动。首次配置必须在 SSH 交互终端运行。

## 2. 首次配置

在管理器中选择 `[01]`。向导将：

1. 扫描 Vaultwarden 容器。
2. 读取容器 `/data` 对应的主机挂载目录。
3. 确认目录中有非空 `db.sqlite3`。
4. 检查备份工具依赖。
5. 配置 GitHub SSH Deploy Key、仓库地址和分支。
6. 配置 age 公钥、备份目录和保留策略。
7. 展示摘要，输入 `yes` 即可保存配置（不区分大小写，`YES`、`Yes` 也可以）。

如已有历史备份，必须使用创建这些备份时的原 age 公钥；不要新生成密钥替代。age 私钥至少离线保存两份，不要提交到 GitHub。

## 3. 首次手动备份

选择 `[02]`，选择上传目标，核对容器名称和 `/data` 主机路径后输入 `yes`。所选的 GitHub 或 WebDAV 目录中会出现加密文件组。

## 4. 验证备份

选择 `[05]`，从 GitHub、本地目录或 WebDAV 选择备份并执行 SHA256、age 解密、tar 内容和 SQLite 检查。离线私钥可以临时提供，检查完从 VPS 删除临时私钥副本。

## 5. 启用自动备份

先完成一次手动备份并验证，再选择 `[14]` 设置定时目标并安装 systemd timer。默认每天 VPS 本地时间 05:20，也可选择每周或每月计划。启用后使用 `[15]` 查看状态。

## 6. 全局命令

每次执行 `sudo bash ./run.sh` 时，启动器都会自动安装或修复 `/usr/local/bin/vbm`。之后在 VPS 任意目录执行 `vbm` 即可进入交互式菜单。

## v1.4.8 菜单重组

当前菜单使用六大分类，完整序号表见 `docs/完整使用手册.md` 第 5 节。升级后请使用 `[22]` 同步已安装后台脚本，使用 `[23]` 检查/更新源码。

`[02]` 选择 GitHub 或 WebDAV 创建新备份；`[05]`、`[06]`、`[08]`、`[09]`、`[10]` 进入后选择 GitHub、本地或 WebDAV；`[14]` 设置 systemd 定时目标、频率和时间。

## 本地清理与 WebDAV

升级源码后运行 `[22]` 同步后台脚本，再执行新增菜单。

- `[10]` 管理历史备份；`[11]` 查看/删除本地备份；`[12]` 配置 WebDAV；`[13]` 上传/补传 WebDAV。
- `[05]` 验证历史备份；`[06]` 查看加密部署清单；`[08]` 恢复生产数据；`[09]` 隔离恢复演练。
- `[22]` 同步已安装后台脚本；`[23]` 检查/更新源码并同步后台脚本。

WebDAV 服务需支持 `PROPFIND / MKCOL / GET / PUT / MOVE / DELETE`。备份保存在所填 URL 下的 `vbm/` 子目录。若 URL 已以 `vbm/` 结尾则直接使用。凭据保存至 `/etc/vaultwarden-webdav.json`，由 root 所有，权限为 `600`。首次部署可在 `[01]` 选择 `webdav`。`[02]` 创建新备份，`[13]` 补传已有密文。

WebDAV 成功备份会按 `RETENTION_DAYS` 自动清理过期本地常规备份，保留恢复前快照和 `.keep` 保护文件。用 `[11]` 手动清理本地备份，或在 `[10]` 选择 WebDAV 后按编号删除远端备份组。WebDAV 远端保留期限由存储服务管理。

## v1.4.8 菜单说明

菜单分为六类：快速操作、备份与验证、恢复与演练、存储与保留、自动化与安全、系统维护。主菜单顶部会显示当前备份目标、最近一次备份、本地服务恢复和远端核验状态。

- `[02]` 选择 GitHub 或 WebDAV 后立即创建并上传新备份。
- `[05]`、`[06]`、`[08]`、`[09]`、`[10]` 进入后选择 GitHub、本地或 WebDAV 来源。
- `[14]` 选择 GitHub/WebDAV 定时目标，并设置频率和时间。
- `[10]` 管理历史文件；`[11]` 固定管理本地目录；`[12]` 配置 WebDAV；`[13]` 上传/补传 WebDAV。
- `[22]` 同步已安装后台脚本；`[23]` 检查/更新源码并同步后台脚本。

## 9. 重要提示

- 源码仓库与备份存储分开；GitHub 备份仓库必须 Private。
- 服务器日常加密只需要 age 公钥，私钥离线保存。
- 备份期间 Vaultwarden 会短暂停止；快照完成后会尽快启动，再上传当前目标。
- GitHub 删除当前分支文件不会清理 Git 历史对象，需留意仓库体积。
- 首次正式依赖备份前，至少进行一次真实解密验证和隔离恢复演练。

`[07]` 可查看备份和恢复的阶段耗时、最近运行统计、指定运行详情并导出 CSV。记录保存在 `/var/lib/vaultwarden-backup/performance.tsv`。源码更新后运行 `[22]` 同步 systemd 使用的后台脚本。确认时可输入 `yes`、`YES` 或 `Yes`。

升级前运行菜单 `[19]`。程序会为本次备份生成独立运行 ID，并要求本地校验、服务恢复和远端核验全部成功。

完整说明见 [完整使用手册](完整使用手册.md)。


## 性能记录排查

手动备份完成后，日志应出现 `[性能] 已启用阶段耗时记录` 和多条 `[耗时]`。检查记录文件：

```bash
ls -lh /var/lib/vaultwarden-backup/performance.tsv
tail -n 20 /var/lib/vaultwarden-backup/performance.tsv
```

如果文件不存在，更新项目后执行菜单 `[22]` 同步 systemd 使用的后台脚本，再用 `[02]` 执行一次手动备份，并在 `[07]` 查看性能记录。
