# 支持矩阵

## 运行要求（硬性）

| 项目 | 要求 |
|---|---|
| 操作系统 | Ubuntu / Debian（使用 systemd） |
| 部署方式 | 1Panel 应用商店、docker compose 或 docker run |
| Vaultwarden | 官方 `vaultwarden/server` Docker 镜像 |
| 数据库 | SQLite |
| 容器数据路径 | 容器内 `/data` 挂载到主机目录（bind mount）或 Docker 命名卷 |
| 权限 | root，或可通过 sudo 管理 Docker、systemd 和系统目录 |
| 远端 | 独立 GitHub Private 备份仓库或 WebDAV HTTPS 专用目录 |

不支持：MySQL / PostgreSQL 外部数据库、容器内非 `/data` 的自定义数据布局（含修改 `DATA_FOLDER`）、非 Docker 的二进制 / systemd 直装、Podman、非 systemd 发行版。

## 实测记录

只记录真实跑通过的组合。「应该能跑」不算实测；欢迎通过 Issue 提交你的实测结果（注明系统、部署方式、1Panel 和 Vaultwarden 版本）。

### v1.6.4 真机一比一验证（2026-11-28）

测试使用发布提交 `c630d5a`、Ubuntu 26.04.1 LTS、Docker 29.10.1 和 Vaultwarden 1.37.5，数据均为合成测试数据。

| 场景 | 通过的功能 |
|---|---|
| Docker 独立绑定挂载、Compose 绑定挂载、Docker 命名卷 | 停机和在线快照、签名、回环 HTTPS WebDAV 上传与回读、验签解密、部署清单、隔离演练、恢复；恢复后数据库标记、附件及 Send 哈希符合预期 |
| Compose 绑定挂载、Docker 命名卷 | `[22]` 同步模块、已安装管理器和 `vbm status`；模拟恢复后首次启动失败，按预期回滚并重新健康启动 |
| GitHub Private | GitHub 单目标及 GitHub + 回环 HTTPS WebDAV；重新克隆并核对六个文件；GitHub 来源验证、清单、演练与恢复；`.keep` 保护、取消保护、按组删除后保留本地副本 |
| 双目标故障（本地 Git 替身 + 回环 HTTPS WebDAV） | Git 或 WebDAV 单侧失败时，另一侧保留核验通过的副本；失败侧入队，连接恢复后补传 |
| 自动化 | GitHub Actions 通过；测试机 ShellCheck error 级、Bash 语法、18 个 Shell 脚本、归档校验、22 个 Python 存储用例均通过，无跳过 |
